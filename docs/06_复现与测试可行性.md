# 复现与测试可行性：候选选择及后续方案

日期：2026-10-23。**本轮仅分析，不执行。**没有安装第三方依赖、建立实验环境、下载模型权重或大规模数据，没有调用实验 LLM、启动数据库、训练、推理或测试。读取的 GitHub 文件仅用于静态审查；运行时间、内存和指标均无本轮实测值。

## 1. 建议先选择什么

| 候选 | 对课题的意义 | 当前工程判断 | 建议 |
|---|---|---|---|
| TLogic | 未来事件预测与可检查规则 | 数据、锁文件和分阶段入口较完整；评估细节需统一 | **首选离线复现候选** |
| AriGraph | 动态图记忆与长任务执行 | 环境文件和对照流程可见；旧模型调用及平台说明需整理 | **首选机制测试候选** |
| RE-GCN | 神经时序图预测对照 | 旧 CUDA/DGL 依赖；多步协议需要澄清 | **解决前置条件后纳入** |
| RAP / LLM Reasoners | 世界模型与搜索的分工 | 有模块接口与 BlocksWorld 实现；后端、评价器待对齐 | **第二阶段的规划对照** |
| ARES-KG | 领域图模式、查询和证据展示 | 是数据与文档工件，不是完整可启动系统 | **可做局部工件核验** |
| DAVIS | 检索近似动态与反馈重规划 | 作者提示不稳定；数据库、多服务与成本较重 | **先读方法，暂缓完整复现** |
| WKM | 参数化知识约束行动 | 两个 OpenAI SDK 精确版本冲突；训练/推理链路较重 | **先解决依赖，暂缓运行** |
| KGLAMP | 知识约束到符号计划 | 本轮未确认作者完整代码 | **保留方法重实现，不承诺原样复现** |
| Worldformer | 最直接的行动条件图转移参考 | 作者实现未确认；数据源可见 | **优先研究任务定义，暂缓完整复现** |

这是研究价值和当前可操作性的综合排序，不是论文质量排名。进一步静态审查改变了首轮仅凭“有仓库”做出的粗略判断。

## 2. 复现、机制测试与方法重实现的区别

**原配置复现**：尽量固定原始代码、数据划分、模型、提示和评估协议，比较论文结果。缺少原模型接口、数据或权重时，不能承诺原样复现。

**机制测试**：可以使用当前可用模型和较小任务集合，但必须让对照组共享模型、环境和预算，回答某个机制是否有帮助。结果不应与旧论文数字直接比较。

**方法重实现**：根据论文自行实现算法或组件。需要公开偏离原文的设计，不能把新实现的失败当成原方法失败。

本轮建议：TLogic 尽量靠近原配置复现；AriGraph 优先考虑机制测试；缺少实现的 KGLAMP、Worldformer 暂时属于方法重实现候选。

## 3. 逐项静态可行性

### 3.1 TLogic：优先考虑

核验版本：`9f6ffa3cc5c112226dc2537983b6bb33d4ef295e`。

| 维度 | 已看到的证据 | 含义 |
|---|---|---|
| 环境 | `pyproject.toml` 要求 Python ≥3.9 且 <3.11；依赖以 NumPy、pandas、joblib 等为主 | 不需要把 LLM/API 或神经训练作为起点 |
| 数据 | 树中含 ICEWS14/18/0515 数据文件、ID 映射及统计 | 路径较完整；本轮未加载全量数据或验证内容 |
| 流程 | `learn.py`、`apply.py`、`evaluate.py`，另有 `run.txt` 与演示笔记本 | 可分开分析规则学习、应用和排序 |
| 可复现设置 | 原命令给出种子与并行数 | 作者说明并行数可影响规则学习，不能只固定种子 |
| 评估 | `calculate_rank` 默认并列排名为 `best`；有时间条件过滤 | 与其他实现比较时需明确相同口径 |

来源：[依赖](https://github.com/liu-yushan/TLogic/blob/9f6ffa3cc5c112226dc2537983b6bb33d4ef295e/pyproject.toml)、[原命令](https://github.com/liu-yushan/TLogic/blob/9f6ffa3cc5c112226dc2537983b6bb33d4ef295e/mycode/run.txt)、[评价器](https://github.com/liu-yushan/TLogic/blob/9f6ffa3cc5c112226dc2537983b6bb33d4ef295e/mycode/evaluate.py)。

后续最小研究问题：历史时序规则相对于频率/近期事件基线，是否改善未来对象排序，并提供可检查的命中路径？建议先只选一个完整时间划分的数据集；若只做小样本机制检查，应明确结果不对应整套论文指标。

资源规划建议：普通 CPU 工作站起步，预留多进程内存；先保留原并行数与单进程设置的区别。不把“无 GPU 依赖”写成“必定很快”。达到原规则长度、游走次数后的耗时和峰值内存仍待未来测量。

### 3.2 AriGraph：最贴近任务规划的优先候选

核验版本：`e884b76d7fa5185a3a8a55e5a67393b5a43f5ef2`。

环境目录中可见 TextWorld 游戏文件；同一仓库有图记忆及全历史、摘要、RAG 等对照入口，适合隔离记忆机制。`pipeline_arigraph.py` 的规划、动作模块仍指定旧模型名称，不能只修改一个模型变量就认为所有模块已切换。检索设备默认是 CPU，因此“必须本地大 GPU”并非该入口的直接要求；实际编码模型内存仍需另行确认。

README 一方面称受 TextWorld 影响只支持 Linux，另一方面列出 macOS 系统依赖说明。它们不足以构成 macOS 已验证兼容的证据。建议未来先选 Linux 环境，避免当前工作机安装过程掩盖研究问题。

来源：[README](https://github.com/AIRI-Institute/AriGraph/blob/e884b76d7fa5185a3a8a55e5a67393b5a43f5ef2/README.md)、[入口配置 L18–42](https://github.com/AIRI-Institute/AriGraph/blob/e884b76d7fa5185a3a8a55e5a67393b5a43f5ef2/pipeline_arigraph.py#L18-L42)、[依赖](https://github.com/AIRI-Institute/AriGraph/blob/e884b76d7fa5185a3a8a55e5a67393b5a43f5ef2/requirements.txt)。

后续最小研究问题：同一模型、相同环境和预算下，语义图加情景记忆是否比摘要或普通 RAG 更能完成长任务？首先选一类小环境，再增加难度；不以一次成功轨迹代表稳定性能。需要明确“预算”是总 token、总调用次数还是最大动作数，三者都应记录。

预期前置修改：统一模型配置、凭据改用环境配置、保留真实 usage 数据、检查提示中的记忆变量是否生效、核对不同记忆流程的行动模块。以上均为后续工作，本轮没有修改或执行作者代码。

### 3.3 RE-GCN：有价值，但不适合直接在当前环境开跑

核验版本：`bc64211e3346f3fbc8988990969f4809fcca2977`。

原依赖指定 `torch==1.6.0`、`torchvision==0.7.0`、`dgl-cu102==0.5.2`，README 使用 Python 3.7。优先方案是重建兼容的 Linux/NVIDIA 环境；将其迁移到新 PyTorch/DGL 则属于独立工程变更，需要重新核对算子与评估行为。CPU 分支仍可见无条件 `.to(args.gpu)`，故不能仅看 `use_cuda` 判断开关就承诺 CPU 可运行。

仓库树中可见约 21.4 MB 的 `data-release.tar.gz`；它的存在只能证明有数据工件，尚未证明其中的划分与 TLogic 一致。`ICEWS14s` 与其他项目中的 `icews14` 命名不同，也需核对内容，不能直接配成同一排行榜。

来源：[依赖](https://github.com/Lee-zix/RE-GCN/blob/bc64211e3346f3fbc8988990969f4809fcca2977/requirement.txt)、[README](https://github.com/Lee-zix/RE-GCN/blob/bc64211e3346f3fbc8988990969f4809fcca2977/README.md)、[评估与历史更新 L62–99](https://github.com/Lee-zix/RE-GCN/blob/bc64211e3346f3fbc8988990969f4809fcca2977/src/main.py#L62-L99)。

后续最小研究问题：与规则方法相比，神经图演化在同一时间协议下是否更有效？应分别保留在线真值更新、固定历史和预测回写设置。`--multi-step --topk 0` 的示例实际上没有产生回写事实；改成正数也仍使用查询中的已给定字段重建事实，不能由此声称自主生成完整未来态势。

资源规划建议：先确认可获得旧环境兼容的 NVIDIA 服务器；本轮不指定保证可用的显存门槛、训练时长或移植成功率。

### 3.4 RAP / LLM Reasoners：规划机制的备用对照

核验版本：`f94e5ac2cb9788c3d7d7dbf2173884ed4088e4b2`。

框架公开 `WorldModel`、搜索配置与算法接口；BlocksWorld 示例中的状态更新由语言模型生成，再应用到符号状态。它适合未来比较“无搜索/有搜索”“语言转移/确定符号转移”，并检验模型预测错误是否被搜索放大。

不过，库支持多个后端，不代表每个示例都可直接切换。已读入口存在 CUDA 设备与大模型路径配置，因此完整复现仍需检查具体后端、任务文件、评价器及模型接口。[框架](https://github.com/maitrix-org/llm-reasoners)、[状态更新](https://github.com/maitrix-org/llm-reasoners/blob/f94e5ac2cb9788c3d7d7dbf2173884ed4088e4b2/examples/RAP/blocksworld/world_model.py#L49-L94)。

建议放在第二阶段：先有一个可以独立检查的任务状态转换环境，再比较规划收益。这个对照检验搜索与预测的关系，不直接验证知识图谱增强。

### 3.5 ARES-KG：可考虑局部工件核验

核验版本：`e41043cecf2062c373bfd7450d054928d4afbe99`。

仓库可见 CSV 和文档形式的 Cypher 查询/导入材料。适合借鉴本体、数据组织与查询回溯；若后续运行，应先从文档恢复脚本、核对实际工件与论文清单，再检查同一图快照下查询结果的一致性。[作者工件](https://github.com/dimitrisdoumanas19/DSS-ARESKG/tree/e41043cecf2062c373bfd7450d054928d4afbe99)。

这类工作可以形成演示或局部核验，尚不能称为完整闭环决策复现。作者数据的领域、规模和合成性质也限制了泛化结论。若将其方法迁移到应急调度，应重新定义实体和约束，明确属于迁移实现。工程代码/数据的许可未由 API 明确识别，后续复制或再分发前需核查。

### 3.6 DAVIS：先保留方法，暂缓完整实验

核验版本：`19c854cced8588534578eb40023fe7a0869c054f`。

作者 README 主动说明依赖更新后代码可能不稳定。工程要求 Python 3.11、PostgreSQL 表、ScienceWorld 与模型服务；配置示例说明原实现使用 Azure 接口，并存在其他服务配置。读取训练入口可见它沿环境的 gold action sequence 收集经历，因此不能把文件名中的 training 直接理解为训练模型权重，也需保证训练经历和评价任务的划分。

作者对完整实验给出过超过 2000 美元的历史调用费用提示；这是仓库中的历史说明，不是当前报价或本轮成本估算。对我们而言，更需要先估算完整调用链的 token 与重试，避免用单次请求费用外推全实验。[README](https://github.com/minhphd/DAVIS/blob/19c854cced8588534578eb40023fe7a0869c054f/README.md)、[配置](https://github.com/minhphd/DAVIS/blob/19c854cced8588534578eb40023fe7a0869c054f/config/config.ini.example)、[经历收集入口](https://github.com/minhphd/DAVIS/blob/19c854cced8588534578eb40023fe7a0869c054f/ReasonAgentTraining.py)。

建议先研究多轮检索与 critic 的消融设计。若未来要尝试，先限定单任务、单进程和明确调用上限；这只能算接口与机制检查，不能报告论文全任务平均分。

### 3.7 WKM：先解决明确的静态阻塞

核验版本：`f1fe28fc189c59801a98cabda01188bc9b64eae6`。

`requirements.txt` 同时包含 `openai==0.28` 与 `openai==1.25.0`，两个精确版本不能同时满足。此外包含 FlashAttention、训练与多环境依赖。README 的示例涉及代理模型和知识模型两个服务，不能把一个模型可推理当作整个 WKM 已复现。

建议未来先判断每个模块真正需要的 SDK 和依赖，拆分训练/推理环境，而不是不加区分地删除某一行。仓库含训练数据与适配器的外部链接，但本轮没有下载权重或核对全部链接内容；预训练基础模型、适配器和环境资源仍是前置条件。README 许可徽章与根 LICENSE 的信息也应分别核查，以实际适用文件为准。[依赖](https://github.com/zjunlp/WKM/blob/f1fe28fc189c59801a98cabda01188bc9b64eae6/requirements.txt)、[说明](https://github.com/zjunlp/WKM/blob/f1fe28fc189c59801a98cabda01188bc9b64eae6/README.md)、[LICENSE](https://github.com/zjunlp/WKM/blob/f1fe28fc189c59801a98cabda01188bc9b64eae6/LICENSE)。

该工作适合做“参数化知识还是显式图记忆”的后续对照，但目前不是最低成本起点。

### 3.8 KGLAMP 与 Worldformer：方法价值高，直接复现前置不足

KGLAMP 适合借鉴关系/可达性/能力约束及失败修正，但未确认作者完整实现和实验工件。论文中的 MAT-THOR/MAT2-THOR 名称、环境版本与任务配置需对齐。若自行实现，应先限定为少量符号任务，不一开始复刻多机器人视觉仿真全栈。[论文方法与实验](https://arxiv.org/html/2602.04129v2)。

Worldformer 更适合作为行动条件图转移的概念基线。新增核验到 [JerichoWorld 官方数据仓库](https://github.com/JerichoWorld/JerichoWorld)，有数据压缩包和字段说明；这改善了数据可获得性判断，但不补齐作者模型、权重和训练配置。另有[第三方实现](https://github.com/ethanthoma/world-modeling)主动标注尚在开发且未测试，故本轮只把它列为线索，不纳入可靠复现起点。

## 4. 如果后续启动，建议采用的三个方案

以下全部是**待开展方案**。样本量与预算为建议设计，不是实际执行记录；本轮不提供可误触发全量实验的一键脚本。

### 方案 A：TLogic 的事件预测与解释链

目的：建立离线未来事件预测基线，检查规则解释是否真的对应候选得分。

建议顺序：先核对完整数据划分、反向关系和过滤口径，再复现原配置；额外做最近事件和频率基线，以及规则长度/历史窗口的消融。固定种子之外，还固定并行数，并按预先选定的多组种子报告所有结果。

产出应包括规则数、候选覆盖率、MRR/Hits@K、并列排名约定、耗时、峰值内存和少量可追溯规则实例。没有命中规则的查询也要计入结果，不能只展示成功解释。

进入标准：数据许可及版本已核对，环境方案明确。完成标准：有可重复的命令、日志和全查询指标；不把必须达到某个未经核验的 MRR 当成唯一成功标准。明显偏离原结果时，优先排查协议与数据，而非立即调参追分。

### 方案 B：AriGraph 的图记忆增益

目的：在共享代理的前提下检验语义图与情景记忆是否改善长任务。

建议对照：摘要、普通 RAG、语义图、语义图加情景记忆。若仓库没有独立语义图变体，它属于后续新增消融，不能写成作者现成配置。先选一个小环境，以同一 LLM、动作可见性和预算开展重复试验；不同任务实例与随机运行种子分别记录。

主要指标：任务成功率、归一化得分、有效动作比例、动作数、token 和调用次数。若无法提供可靠的状态标注，则不把人工挑选的几条三元组准确率当作完整图质量。

进入标准：旧模型可用性或替代方案明确，TextWorld 平台方案已确认，调用上限已设定。采用新模型时，产出名称为“机制测试”，而非“原指标复现”。同时保存论文使用的汇总方式与所有预定运行的统计。

### 方案 C：RE-GCN 与 TLogic 的协议一致比较

目的：比较神经图演化与规则方法在同一数据、同一历史可见性下的预测行为。

建议先把比较限制在二者共同支持的数据和对象排名任务。逐项对齐实体/关系映射、时间划分、反向查询、真值历史是否更新、同时间多答案过滤、并列排名及未见实体处理。

如果无法得到同一划分或不能保持协议一致，仍可分别记录复现结果，但不制作优劣排行榜。若迁移依赖或修改评价器，应保留原始结果和统一评价器结果两套记录。

此方案不包含任务规划。因此，即使预测指标改善，也需要下一阶段再验证下游决策收益。

## 5. 资源与成本怎样考虑

当前未提供服务器和模型接口条件，因此以下仅是规划分层：

| 资源条件 | 优先考虑 | 暂不优先 |
|---|---|---|
| 只有普通 CPU 工作机 | TLogic 小规模流程与数据协议核验 | 直接训练 WKM、迁移旧 CUDA 全栈 |
| 有 Linux + 兼容 NVIDIA 环境 | RE-GCN，条件允许再考虑模型训练 | 未核对依赖就升级全部库 |
| 有可控预算的 LLM API | AriGraph 小范围机制测试 | DAVIS 全量任务起步 |
| 有图数据库但没有仿真环境 | 图查询与证据工件核验 | 宣称完成规划闭环验证 |

模型接口成本应按真实调用链估算：

\[
\text{总成本}\approx\sum_j
\bigl(T^{\rm in}_j p^{\rm in}_j+T^{\rm out}_j p^{\rm out}_j\bigr)
+\text{基础设施成本}.
\]

其中 token 统计需覆盖检索、抽取、规划、执行判断、重规划和重试；服务价格在后续真要运行时查询，不在本轮假设当前价格。种子控制不能消除商业模型版本变化，所以应保留接口版本、提示、输出与缓存。

## 6. 最终选择建议

**建议后续第一批只做两个方向：TLogic 的离线事件预测，AriGraph 的图记忆机制。**前者让我们建立可靠的预测评价链，后者让我们验证结构化知识是否对长任务有用。RE-GCN 作为条件具备后的神经对照；RAP 作为下一阶段的搜索对照。ARES-KG 可支撑领域资料和查询设计，不作为唯一算法基线。

本轮没有启动这些方案；所有资源、兼容性、运行时长与成功率判断均待未来实际验证。静态发现只能支持排优先级和识别前置条件，不能支持“已经跑通”或“已经复现失败”的结论。
