# 内容详细总结：知识图谱增强的态势预测与指挥决策

本文档对本仓库两轮调研的实质内容做集中总结，与 [README](../README.md) 和各分报告互补。生成日期：2026-10-25。

## 1. 仓库定位与已完成的工作

本仓库是一个**文献调研 + 工程梳理**型仓库，不是实验代码项目。主题是：**能否用知识图谱增强态势预测与任务规划 / 指挥决策**。

截至当前完成两轮工作，日期均为 2026-10-23，且**没有安装依赖、没有运行模型、没有做任何实验**：

- 第一轮：建立基础资料库，收录 21 项论文资料、11 个工程索引、3 篇可再分发的 CC BY 4.0 论文 PDF，核验来源与许可证，提出研究主线。
- 第二轮：补充方法与证据综述、复现可行性评估，以及按固定提交 SHA 对工程做**静态代码审查**（只读文件推理，不运行）。

所有结论都止于文献阅读和静态审查，仓库严格区分「论文报告了什么」「作者声称了什么」「静态推导出什么」和「实际跑通什么」。

## 2. 课题与要回答的问题

态势信息通常多源、局部可观测、随时间变化、关系密集。面对任务目标，系统需要回答三个连续但不同的问题：

1. **当前知道什么**（态势理解）；
2. **未来可能发生什么**（态势预测）；
3. **采取什么行动能改善结果**（行动条件预测与规划）。

调研将「指挥决策」限定为**辅助人类理解态势、比较任务方案、配置资源**的研究目标，先用公开的应急调度或文本交互环境讨论验证方式。

## 3. 统一分析框架

### 3.1 三个必须分开评价的能力

| 能力 | 含义 | 典型任务 |
|---|---|---|
| 态势理解 | 当前哪些事实成立 | 图问答、关系补全、意图识别 |
| 态势预测 | 已知历史，未来更可能出现什么事件 | 时序图外推、未来链接排序 |
| 行动条件预测与规划 | 不同动作下未来状态、代价、可行性有何不同 | 图状态转移、符号规划、重规划 |

三者要求的数据和证据不同，不能放进同一张准确率排行榜。历史相关性也不等于干预因果性：图上写有「导致」关系，仍要检验关系来源、成立条件和干预证据。

### 3.2 知识图谱的五个增强位置

| 增强位置 | 典型技术 | 期望收益 | 应优先验证的量 |
|---|---|---|---|
| 状态表示 | 本体、语义图、情景记忆 | 减少事实碎片化与记忆遗失 | 状态正确率、过时事实比例 |
| 动态预测 | 图演化网络、时序规则、图增量生成 | 更准预测事件或状态变化 | 时间外推指标、多步误差 |
| 行动生成 | 能力图、可达图、前置条件 | 减少不可执行动作 | 动作有效率、计划可行率 |
| 方案评估 | 规则约束、价值模型、搜索 | 选出收益更高的方案 | 成功率、代价、搜索预算 |
| 解释与复核 | 图查询、证据路径、来源记录 | 支持检查依据与失效原因 | 证据覆盖、解释忠实性 |

上述收益是待验证假设；「使用知识图谱」本身不能替代任何一行指标。

### 3.3 四类不能互换的证据

1. 出版和方法描述；
2. 离线预测或问答实验；
3. 仿真交互任务结果；
4. 真实场景闭环验证。

这不是质量排名，而是结论适用范围：设计严谨的离线实验可以有力支持预测方法，却不能证明实际决策收益。

## 4. 五条研究路线与代表工作

调研把「世界模型」这个模糊词拆成五种技术对象：

| 路线 | 技术对象 | 代表工作 |
|---|---|---|
| 潜在世界模型 | 学隐式环境动态，在想象里优化行为 | World Models、DreamerV3 |
| 显式图动态 | 直接学「动作如何改变图状态」 | Worldformer |
| 时序图预测 | 从历史事实图外推未来事件 | RE-GCN、TLogic、TiRGN、TGB 2.0 |
| 图记忆与约束规划 | 用图组织记忆，或把知识转成可执行计划 | AriGraph、DAVIS、WKM、RAP、KGLAMP |
| 领域决策支持 | 用图做查询、证据、解释 | E-KELL、ARES-KG、Graphiti、GraphRAG、KnowVal |

### 4.1 潜在世界模型线

World Models（2018）与 DreamerV3（Nature 2025）提供闭环思路：先学环境动态，再在想象轨迹上改进行为。它们适合当「预测必须服务于行动」的参照，但表示通常不是可查询的领域知识图谱，不能直接复用为指挥系统。

### 4.2 显式图动态线

Worldformer 输入观测、状态图、有效动作与执行动作，输出下一状态的图变化与有效动作集。它说明图世界模型可以定义为明确的监督学习任务，不必先生成整段视频。局限是证据在文本环境、作者代码未确认，且「环境提供状态与有效动作」这一前提在真实系统中未必成立。

### 4.3 时序图预测线（最可复现的切口）

RE-GCN 用关系图卷积 + 循环演化表示历史图；TLogic 从时序路径学规则并预测未来链接；TiRGN 补充局部与全局历史模式。这条路线的输入输出较明确，容易先建立基线。

需要区分两种预测：给定查询中的主体、关系、时间排序对象，以及从当前状态主动生成未来全部重要事件。前者指标好也不自动具备后者的覆盖能力，更没有直接决定行动方案。

### 4.4 图记忆与约束规划线

AriGraph 把语义图与情景记忆连接，回答「当前知道什么、知识来自哪些经历」；DAVIS 把转移经历写入时序图，用多轮检索近似未来变化与奖励，再结合批评与重规划；WKM 区分任务知识与状态知识；KGLAMP 把关系、可达性与能力图转成 PDDL 问题并支持重规划；RAP 用 LLM 兼任世界模型，配合 MCTS 搜索。

调研强调：图记忆是规划的有力支撑，但「记忆方法优劣」和「动态预测方法优劣」要分开实验；只有任务成功率提高，不足以确定收益来自预测、检索还是更多模型调用。

### 4.5 领域决策支持线

E-KELL 构建应急知识图谱并通过提示链提供决策支持；ARES-KG 以图查询和显式依赖做可追溯分析；中文三篇（态势估计、行动判识、意图识别）补充领域术语与子任务定义；Graphiti、GraphRAG 是动态记忆或文档检索基础设施，本身不预测未来、不做规划闭环；KnowVal 属自动驾驶迁移参考。

## 7. 第二轮静态审查关键发现

完整记录见 [07_第二轮证据审查.md](07_第二轮证据审查.md) 与 [round2_static_audit.json](../data/round2_static_audit.json)。要点：

- RE-GCN 的 README 多步示例 `--topk 0` 在代码中不写回预测事实，历史列表保持不变，不能称为「完整自主图演化」。
- RE-GCN 的 `.to(args.gpu)` 无条件调用，光看 CPU 开关不能保证 CPU 可运行。
- TLogic 的 `calculate_rank` 默认并列排名为 `best`，与其他实现比较需统一口径。
- AriGraph 的规划/动作模块写死旧模型名，只改一个变量切不完所有模块；检索设备默认 CPU。
- DAVIS 的 `ReasonAgentTraining.py` 按 gold action sequence 收集经历，文件名里的 training 不等于训练模型权重。
- WKM 的 `requirements.txt` 同时要求 `openai==0.28` 与 `openai==1.25.0`，无法同时满足。
- ARES-KG 仓库主要提供数据与文档形式的查询材料，论文声称工件与仓库实际文件是否一致需继续核对。

这些是读代码得出的前置条件判断，不是实测成功或失败。

## 8. 三个可证伪的研究问题

1. **时间与置信度是否比扩大图规模更有用？** 对比静态图、仅时间戳图、带有效期与来源的图，在一致事件流上测量状态误差、事件排序与下游收益。
2. **图记忆何时应触发重规划？** 只在关键前置条件失效时重规划，是否比每步重生成整段计划更省预算。
3. **预测更远是否一定决策更好？** 长预测跨度可能因误差累积降低计划收益，需要找适合任务的预测范围。

对应实验设计（对照、消融与指标）见 [01_调研报告.md](01_调研报告.md) 第 6 节与 [05_综述报告.md](05_综述报告.md) 第 6 节。

## 9. 后续三个实验方案

详细设计见 [06_复现与测试可行性.md](06_复现与测试可行性.md)。均为**待开展方案**：

- **方案 A：TLogic 事件预测与解释链**。先核对数据划分、反向关系与过滤口径，复现原配置；再加最近事件/频率基线，做规则长度与历史窗口消融。产出规则数、覆盖率、MRR/Hits@K、并列约定、耗时与峰值内存。
- **方案 B：AriGraph 图记忆增益**。同一模型、环境、预算下比较摘要 / 普通 RAG / 语义图 / 语义图 + 情景记忆。指标为任务成功率、有效动作比例、动作数、token 与调用次数。
- **方案 C：RE-GCN 与 TLogic 协议一致比较**。对齐实体/关系映射、时间划分、历史可见性、并列规则与未见实体处理，比不了就不做优劣排行榜。

优先级建议：先做 TLogic 离线预测与 AriGraph 图记忆机制；RE-GCN 在解决旧依赖后作神经对照；RAP 作第二阶段搜索对照。

## 10. 当前边界与建议下一步

本仓库目前**没有任何实测结果**：所有排序、可行性判断与前置条件都来自文献阅读和静态审查。它是一张已经画好路线、标好坑位的研究地图，但地图上还没有一处被真正走过。

下一步的自然动作是：按方案 A 或方案 B，固定工程 SHA、记录环境与命令，启动第一个可重复的复现，并把 `execution_status` 从 `not_run` 改为有日志支持的状态。
