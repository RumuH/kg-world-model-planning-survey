# 项目负责人咨询清单与需求卡

日期：2026-10-25。用途：把文献调研与项目实际任务对齐。当前尚不了解项目细节，以下是建议咨询的问题，不代表项目已有这些条件。

## 先确认六项信息

| 优先项 | 可以直接问的问题 | 为什么重要 |
|---|---|---|
| 具体场景 | 这个项目主要给谁用？在哪个环节使用？当前最难解决的一个问题是什么？ | 明确需要改善的实际工作，避免仅围绕模型名称选论文 |
| 预期输出 | 系统最终要输出未来事件、态势指标、任务分解、资源分配、行动序列，还是带依据的建议？ | 决定重点研究预测、规划还是知识支持回答 |
| 完整样例 | 能否给一条可共享的输入及其理想输出，并说明它为什么算正确？ | 把抽象需求转换成可以理解和验证的任务 |
| 数据条件 | 现在有哪些数据和图谱？是否有时间戳、行动及其后续结果？有没有回放或仿真环境？ | 决定能研究历史预测、动作后果还是闭环规划 |
| 评价与基线 | 目前采用什么方法或人工流程？项目用什么指标验收？最不能接受哪类错误？ | 确定论文的收益能否转化为项目收益 |
| 责任与交付 | 我们具体负责哪个模块？目标是论文、算法原型还是系统功能？近期里程碑是什么？ | 确定调研深度和复现范围 |

如果交流时间有限，先问“输出是什么、给一个完整例子、有哪些数据、如何判断有效”。先拿到这些信息，已经能大幅缩小文献范围。

## 有了场景后，再追问技术条件

### 1. 时间、空间与动作粒度

- 预测下一事件、固定时刻状态，还是一段演化轨迹？预测跨度多长？
- 数据按秒、分钟、小时还是任务阶段更新？需要多久给出结果？
- 输出是一个动作、若干任务分工，还是从开始到结束的完整方案？
- 存在多个协同主体吗？能力、资源、权限、时序和互斥约束有哪些？哪些是硬约束，哪些是偏好？

这些信息决定时序图模型、记忆、搜索和符号规划是否必要。任务使用“指挥决策”这一名称，并不足以确定动作空间。

### 2. 观测与知识图谱

- 当前状态能否完整观察？哪些信息缺失、延迟或存在冲突？
- 图谱是否已经建成？实体、关系、时间和来源如何定义？
- 图谱主要保存静态知识，还是持续更新的状态和事件？
- 是否需要我们负责知识抽取、本体设计、实体对齐或图更新，还是只使用既有图谱？
- 项目是否要求必须使用某种世界模型或知识图谱技术？这个要求来源于研究假设、已有架构还是交付约束？

如果图谱建设本身是主要工作，应补查知识抽取和动态知识质量，而不直接进入规划算法比较。

### 3. 数据与动作反馈

- 数据来自报告、日志、仿真、传感器还是人工标注？量级和时间跨度如何？
- 实体是否有一致的标识？关系类型、事件时间和事实有效时间能否区分？
- 是否记录“状态、采取的行动、行动后的状态、任务结果”？
- 能否按时间划分训练和评价数据？哪些样本可以用于调研或实验？
- 若没有真实行动反馈，有没有可信的规则模拟器、回放系统或可交互环境？

只有历史事件通常可以研究预测，尚不足以独立评价改变行动造成的效果。有行动记录时还应考虑动作选择偏差，不能自动作因果解释。

### 4. 当前系统与实际瓶颈

- 现有系统由哪些模块构成？我们新增模块的输入输出接口是什么？
- 当前最明显的失效案例是事实错误、预测不准、记忆丢失、违反约束、执行失败还是响应过慢？
- 团队已有模型、规则、规划器、图数据库或数据处理流程吗？
- 希望调研的产出是直接复用工程、提出改进点，还是验证某个技术假设？

同一篇论文，对不同瓶颈的价值可能完全不同。最好请负责人给一例目前系统做不好的案例。

### 5. 评价、资源和交付

- 主要评价未来事实准确率、任务完成率、方案代价、约束满足、专家认可还是证据可追溯性？
- 是否有独立的真值或评价器？是否能回放执行结果？需要人参与最终决策吗？
- 部署是否限制外部模型接口？可用算力、软件平台、数据库和调用预算是什么？
- 近期交付时间和优先级是什么？达到什么程度算第一阶段完成？

资源条件会影响后续候选排序，但应放在任务和评价之后讨论，避免先被某个现成工程牵引。

## 回答如何影响文献选择

| 负责人确认的重点 | 下一轮优先参考 | 需要额外注意 |
|---|---|---|
| 带时间的事件预测 | RE-GCN、TLogic、TGB 2.0 | 数据划分、历史可见性与排名协议 |
| 持续状态维护和长期记忆 | AriGraph、Graphiti | 更新、冲突、过时事实与记忆预算 |
| 不同动作的后果 | Worldformer、DAVIS | 动作条件数据、预测误差与独立评价 |
| 约束下的任务分解或计划 | KGLAMP、RAP / LLM Reasoners | 动作模型、前置条件和可执行性 |
| 基于领域规范的辅助分析 | E-KELL、ARES-KG | 证据覆盖与专家评价，区分问答和执行收益 |

这张对应表是基于现有文献的选择建议，不是项目架构结论。论文原始来源见[论文卡片](02_论文卡片.md)。

## 可以直接发给负责人的文字

> 老师/负责人您好，我目前负责“知识图谱增强的态势预测与指挥决策”的文献调研，已梳理了事件预测、图记忆、动作后果预测和约束规划几条路线。为了让后续调研与项目更贴近，想请您帮我确认：
>
> 1. 项目给谁用，主要解决哪个具体场景或痛点？
> 2. 最终希望输出什么？能否提供一条输入和理想输出样例？
> 3. 目前有哪些数据、知识图谱，以及行动后的结果记录或仿真环境？
> 4. 现有方法是什么，项目主要用什么指标评价改进？
> 5. 我们负责哪个模块，近期希望交付论文思路、算法原型还是系统功能？
> 6. 后续验证有哪些算力、模型接口、部署和时间限制？
>
> 如果方便，也希望看看现有任务说明或一次典型案例。我会据此把文献整理成对应模块的参考方案、数据要求与验证建议。

以上是供你自行发送或口头使用的草稿，没有代你联系任何人。

拿回需求卡后，可以进一步整理“项目需求、对应论文、适用条件、缺失数据、可验证假设”的映射表，再决定是否启动某项复现。本轮仍不开展模型测试。
